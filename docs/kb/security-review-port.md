# DittoMac (Swift port) security review

Independent static review of `Sources/DittoCore`, `Sources/DittoMac`, `Resources/` and `scripts/` (2026-11-23).
Threat model: clipboard contents, imported files (`Ditto.db`, `.dittoclips`) and LAN peers are attacker-controlled.
A Friends peer that knows the passphrase is trusted to send clips, but must not be able to exhaust memory, read
files or make DittoMac connect elsewhere (`docs/kb/friends-protocol.md`). The upstream (Windows) review is in
`security-review-upstream.md`.

Verification: `swift build --scratch-path /private/tmp/claude-501/dm-build-sec` and `scripts/test.sh`
(88 tests, all passing). The regression tests are in `Tests/DittoCoreTests/ContentSafetyTests.swift`.
Nothing was exploited at runtime.

## Findings

Line numbers are those after the fix.

| # | Severity | Location | Issue | Resolution |
|---|---|---|---|---|
| P1 | High | `Sources/DittoMac/UI/PreviewWindow.swift:188` (was `sanitizeHTML`), `Sources/DittoMac/Services/PasteService.swift:19` | HTML clips go to the WebKit-based `NSAttributedString` HTML importer, which fetches subresources. The preview's regex blacklist could be bypassed in several ways: `<img/src=https://…>` (slash instead of space), entity-encoded schemes (`src="&#104;ttps:"`), `<svg><image xlink:href=…>`, CSS escapes (`url(\68ttps://…)`), `<frame src>`, `<table background>` with entities. `PasteContent.text(from:)` called `NSAttributedString(html:)` on the **unsanitised** HTML (used by transforms, multi-paste, QR, web search and share on HTML-only clips). Opening or transforming a clip from a web page, a Friends peer or an import could reveal the user's IP and act as a tracking beacon, or start SMB/`file:` lookups. | **Fixed.** New allow-list sanitiser `HTMLSanitizer` (`Sources/DittoCore/ContentSafety.swift:67`) parses with `XMLDocument` (tidy, no external entities) and writes back only allow-listed elements and attributes. It never writes `img`/`svg`/`style`/`link`/`base`/`meta`/media/form/frame elements, and never writes `src`, `background` or `on*` attributes, namespaced attributes, or CSS containing `url`/escapes/`@`/`image`. Text and attribute values are re-escaped, nesting depth is capped, and input above 2 MiB becomes escaped plain text. All HTML rendering now goes through `SafeRichText.html` (`Sources/DittoMac/UI/SafeRichText.swift`). Tests: `blocksBypassesOfTheOldRegexBlacklist` and 4 more. |
| P2 | Medium | `PreviewWindow.swift:183-190` (RTF/HTML), `EditorWindow.swift:173` | Rendered RTF `HYPERLINK` fields and HTML `<a href>` became clickable `.link` attributes in a selectable `NSTextView`. A click calls `NSWorkspace.open` for any scheme: `file:///…/x.command` or `.app` (code launch, Gatekeeper permitting), custom app URL schemes, `smb://` and so on. | **Fixed.** `LinkPolicy.isSafeToOpen` (`ContentSafety.swift:19`) allows only `http(s)` URLs that have a host, and `mailto`. The preview strips other links (`SafeRichText.removingUnsafeLinks`). The editor keeps the RTF unchanged but swallows unsafe link clicks (`textView(_:clickedOnLink:at:)`). The HTML sanitiser drops unsafe `href`s. Test: `linkPolicy`. |
| P3 | Medium | `Sources/DittoMac/Services/FriendsService.swift:186-190` | `FriendsLink.maxInbox` was checked only in `pump()`, after its `guard !busy` early return. While a clip was being stored on the main actor, a peer could keep streaming 16 MiB clip frames and each was appended to the inbox without limit (unbounded memory). This broke the documented "cannot allocate unbounded memory" property. | **Fixed.** The cap is enforced on arrival in `ingest`, and the frame loop stops once the link is closed. `maxInbox` is lowered from 8 to 2, because the protocol is lock-step and an honest peer never has more than one queued message. Worst case per link is now about 16 MiB of buffered frame plus 2 queued clips. |
| P4 | Medium | `FriendsService.swift:136-140,173` | The server sent its Hello (a fresh `HMAC(longTermKey, …)`) to any LAN host as soon as it connected. Anyone on the network could collect material for **offline passphrase guessing** without watching legitimate traffic, limited only by PBKDF2. | **Fixed.** The client speaks first. The server builds its Hello but sends it only after the client's Hello MAC has verified. This is wire-compatible with existing clients, which always send first. Remaining exposure: a passive sniffer of a real session, or a host spoofing a saved peer address, still gets a MAC (documented). |
| P5 | Medium | `Sources/DittoCore/ImportExport.swift:111,150-173`, `SQLite.swift:46` | Imported SQLite files were opened read-only but otherwise trusted. `Main`/`Data` could be **views**: an endless recursive CTE hangs the app on the main thread, and a view or trigger expression could call functions. Every `ooData` blob was loaded with no size limit (up to SQLite's 1 GB per value), and `mText` was unbounded. | **Fixed.** `openUntrusted` sets `trusted_schema=OFF`, `query_only`, `cell_size_check` and `mmap_size=0`, and refuses the file unless `Main` and `Data` are real tables. Formats over `maxImportFormatBytes` (64 MiB) are skipped in SQL (`length(ooData) <= ?`). Text columns are truncated with `substr` (100k characters; format names 256). Tests: `importRejectsViewsInsteadOfTables`, `importSkipsOversizedFormatsAndTruncatesText`. |
| P6 | Medium | `PreviewWindow.swift:194`, `PasteService.swift:107-110`, `QuickPasteActions.swift:522` | Image clips (from peers, imports or web pages) were fully decoded with `NSImage(data:)`/`NSBitmapImageRep(data:)` before any size check. A few-KB PNG can declare 12k×12k or more pixels, so this was a decompression bomb using hundreds of MB to GB. The stitch path checked its 16k cap only after decoding. | **Fixed.** `ImageProbe` (`ContentSafety.swift:168-200`) reads the pixel size from the header. The preview fully decodes only images up to 100 MP and shows larger ones as an 8192 px ImageIO thumbnail. Stitch and PNG export check dimensions before decoding. The list thumbnails already used bounded ImageIO thumbnails. Test: `imageProbeRefusesDecompressionBombs` (an 18 KB, 144 MP PNG). |
| P7 | Low | `FriendsService.swift:83` | The handshake timeout was 30 s. With 4 server slots, an attacker could hold all slots with idle connections for 30 s each. The per-IP block after 5 failures helps, but the attacker can rotate addresses on the LAN. | **Fixed (mitigated).** Lowered to 10 s. PBKDF2 is never part of the handshake because the key is cached. Residual risk is below. |
| P8 | Low | `scripts/test.sh:13` | `"${EXTRA[@]}"` with an empty array is an "unbound variable" error under `set -u` in macOS's bash 3.2. On machines without the plugin directory the test script (and `release.sh`) aborted. | **Fixed.** Uses `${EXTRA[@]+"${EXTRA[@]}"}`. |
| A1 | Info | `ClipStore.swift`, `SearchQuery.swift`, `ImportExport.swift` | SQL injection | **No issue.** Every value is bound. Dynamic SQL is built only from constant fragments, whitelisted column names, or integer constants (`maxImportTextChars`). LIKE/GLOB metacharacters are escaped. `PRAGMA table_info` names are constant. Files are opened without `SQLITE_OPEN_URI`. |
| A2 | Info | `FriendsProtocol.swift` | Crypto | **No issue found.** The key comes from local-constant PBKDF2-SHA256 (600k). The Hello MAC covers role, nonce and name, which blocks reflection, and is checked in constant time by CryptoKit. HKDF salt is both nonces, so every session has fresh keys and replay fails. Keys are per direction, ChaChaPoly uses a counter nonce, the exact next counter is required, AAD includes the direction, the first frame must be Confirm, and state advances only on success. No version negotiation, so no downgrade. **Update (protocol v2):** forward secrecy added with ephemeral X25519 per session, mixed with the PSK in HKDF; ephemeral public keys are inside the Hello MAC and the HKDF salt. Accepted: the session keys are not bound to the full Hello transcript. Names are MAC'd separately and both nonces go into the keys, so an active attacker without the key gains nothing. |
| A3 | Info | `FriendsService.swift:38-54,302-310` | Listener exposure | **Accepted.** `NWListener` binds all interfaces, but every inbound remote address is checked against loopback, RFC1918, link-local and ULA. IPv4-mapped IPv6 is unwrapped, and IPv4-compatible, NAT64 and 6to4 forms are rejected. Outbound links re-check the resolved address. Remotes on a VPN that uses RFC1918 ranges count as "local", and they still need the passphrase. |
| A4 | Low | `Keychain.swift` | Keychain | **Accepted.** Generic password, `AfterFirstUnlockThisDeviceOnly`, never logged, never in UserDefaults. On macOS the legacy file keychain ignores the accessibility class unless `kSecUseDataProtectionKeychain` is set. That needs a keychain-access-group entitlement and a real signing team, which ad-hoc builds don't have. The access control list is bound to the ad-hoc code signature. |
| A5 | Low | `ClipboardMonitor.swift:11-19,126` | Concealed clips | **No issue.** `org.nspasteboard.Concealed/Transient/AutoGenerated`, 1Password and others are checked before anything else, including "save current clipboard" (`force`). The check cannot be disabled. |
| A6 | Low | `CopyRules.swift`, `SQLite.swift:RegexCache` | Regex backtracking | **Accepted.** Patterns are written by the user (copy rules, regex search). Attacker-controlled input is capped at 100k UTF-16 units, but a badly written pattern can still backtrack for a long time. ICU has no time limit through `NSRegularExpression`. The fixed patterns (colour codes, RTF `\par`) are linear. |
| A7 | Low | `QuickPasteActions.swift:255-266` | URL opening | **No issue.** Web search and translate accept only `https` templates and encode the text through `URLComponents`. The only other `NSWorkspace.open` calls use constant URLs. |
| A8 | Low | `ImportExport.swift:299`, `QuickPasteActions.swift:534-575` | Export names and permissions | **No issue / accepted.** `textFileName` replaces `/ : \` and control characters, strips leading dots, adds an index prefix and caps the name at 60 characters, so path traversal is not possible. Multi-file export never overwrites existing files. `.dittoclips` exports, backups and the database are `0600` and the database directory is `0700`. SQLite gives `-wal`/`-shm` the database file's mode. Plain text and PNG exports use the user's umask, because the user chose to export them. |
| A9 | Info | `Resources/*.plist`, `scripts/*.sh` | Signing and scripts | **No issue.** Hardened runtime is on and the entitlements are empty (no JIT, no unsigned library loading, no `get-task-allow`). Version strings are checked against a regex before `sed`, variables are quoted, `rm -rf` targets only paths under the repo or a `mktemp -d` directory, and `trap` handles cleanup. `NSAppleEventsUsageDescription` is unused but harmless. |
| A10 | Info | `FriendsService.swift:491-515` | Received clips | **No issue.** Formats are filtered to text, RTF, HTML, PNG and TIFF (no `file-url`). Peer strings are sanitised and used only for display. Received clips are never echoed to auto-peers. Auto-put marks the pasteboard as internal. |

## Doc vs implementation (`friends-protocol.md`)

| Claim | Status |
|---|---|
| Off by default, passphrase of 12 or more characters, stored in the Keychain | Holds |
| At most 4 server connections; 5 failed handshakes in 10 min blocks the IP for 10 min | Holds. Handshake timeouts also count as failures. |
| Bounded inbox; peer cannot allocate unbounded memory | **Did not hold** (P3); fixed |
| Handshake timeout "~5 s" (app duty) / "30 s" (integration section) | The two statements disagreed. Now 10 s and documented. |
| Never connect to peer-supplied addresses; re-check resolved address | Holds. No message has a host field, and the address is looked up from Settings by peer id. |
| KDF off the main thread, cached | Holds |
| Drop the connection on any `FriendsError` | Holds. Any thrown error closes the link. |
| Only allowed formats kept, peer strings display-only | Holds |

## Residual risks

- **Passphrase strength.** Captured Hello MACs (sniffed from a real session) still allow offline guessing at PBKDF2-600k speed. A 12-character human-chosen passphrase may be guessable. The UI should push users toward long random passphrases.
- **Trusted peers.** A peer that knows the passphrase can fill the disk with up to 16 MiB clips, one acked clip at a time. Retention settings apply later. Its HTML, RTF and images are now rendered safely, but the Cocoa RTF and ImageIO parsers remain attack surface for memory-safety bugs in the system frameworks.
- **LAN DoS.** An attacker who rotates IP addresses can keep the 4 handshake slots busy (10 s each). This only stops Friends; nothing else is affected.
- **Imports.** Real tables can still hold large values and many rows. Memory is bounded per format (64 MiB) and per text column, but the number of rows is not. Imports run on the main thread.
- **HTML fidelity.** The sanitiser removes images, CSS that uses `url()`/escapes, and `<style>` blocks, so some HTML clips render plainer in the preview. Stored data is unchanged.
- **At-rest data.** The clip database is not encrypted beyond `0600` permissions and FileVault. Any process running as the user can read it.
- **Ad-hoc signing.** No Developer ID or notarisation. Users must trust the published SHA-256. The Keychain ACL and the Accessibility grant are tied to each build's code hash.
- **Pasteboard markers.** Protection depends on the source app setting the concealed or transient markers. Apps that don't set them (and the excluded-apps list) are outside DittoMac's control.
