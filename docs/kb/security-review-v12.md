# DittoMac 1.2 security review (vault, upload, screenshots, sync, themes)

Independent static review of the code added in 1.2 (2026-11-25), with fixes. Threat model: clipboard contents,
imported and synced files, upload responses and the network are attacker-controlled. Someone with brief access to an
unlocked Mac (but not your Mac password or DittoMac password) is in scope for the vault. Earlier findings are in
`security-review-port.md`; they were not redone. Spot checks found no regressions: the HTML sanitiser (P1),
link policy (P2), image-bomb probe (P6) and Friends caps (P3/P4) are still in place on the new code paths.

Verification: `swift build --scratch-path /private/tmp/claude-501/dm-build-sec2` (no errors, no new warnings) and
`scripts/test.sh` (257 tests, all passing). The new regression tests are in
`Tests/DittoCoreTests/SecurityReviewV12Tests.swift`. Nothing was run against the real screen, network or Keychain.

## Findings

The `NSLog` on failure printed the path. | **Fixed.** Locked notes are staged only while unlocked (an explicit check, in addition to the empty formats). They get a neutral name ("Locked note N") and mode 0600, and their folders are tracked. `purgeLockedStaging()` runs on every lock: auto-lock, sleep, screen lock, ⇧⌘L and reset. `purgeAllStaging()` removes the staging area and leftover `DittoMac-Share-*` PNGs at launch and at quit. Log lines no longer include paths. |

Preview, desktop notes and the list already re-rendered as "Locked note". | **Fixed.** The editor watches `.dittoVaultChanged`. With no unsaved changes it closes. With unsaved changes it takes the text out of the window (clears undo) and puts it back after the next unlock. Save asks to unlock first. `WindowRouter` closes Properties and Compare windows that show locked clips, and a QR window made from a locked note. |

## Residual risks (accepted)

- **`.system` vault method is an app-level gate.** The data key is a Keychain item readable by anyone or anything
  that runs as you and can unlock the login Keychain. The Touch ID / password prompt protects against casual use of
  DittoMac's UI only. The **password method is cryptographic**: without the password, the database and the Keychain
  item are not enough, and each guess costs PBKDF2 at 600k rounds.
- **Unlocked session.** While unlocked, the key and decrypted notes are in process memory, and pasted text lands on
  the general pasteboard (marked Concealed). Unsaved edits made just before a lock (sticky notes, editor) are kept
  in memory until the next unlock so they aren't lost. A thumbnail that was still being generated when the vault
  locked can end up in the in-memory cache. It is never drawn while locked.
- **Back-off is in memory.** Restarting DittoMac resets the counter. Offline guessing is limited by PBKDF2 anyway.
- **Auto-lock timing.** The inactivity timer can fire late if macOS App Nap throttles the app. Sleep, screen lock
  and fast user switching lock immediately through notifications ("Lock on sleep", default on). A crash loses the
  key (memory only), and staged drag files are removed at the next launch.
- **Vault reset needs no authentication.** It is only destructive (typed `DELETE`), never revealing: it is the way
  out of a forgotten password.
- **Drag-out race.** If the vault locks while Finder is still copying a dropped locked note, the copy may fail.
  A file the user dropped somewhere else is a deliberate plaintext copy.
- **Sync metadata.** `sync-index.json` (0600, local) can still hold the content hash of a clip that was indexed
  before it was locked. **Deletions are not synced.** Another Mac keeps clips you delete here. Modification times
  and sizes leak activity. Backups are pruned by device name, so two Macs with the same name share one rotation.
- **Uploads are public links to a third party you choose.** Anyone with the link can view the image. "Secret"
  0x0.st links are only hard to guess. A custom endpoint can be any https host, including a private IP; its URL
  is kept in preferences, so put tokens in the Keychain-backed header, not in the query string.
- **Permissions after re-signing.** DittoMac is ad-hoc signed. After each update, macOS may treat it as a new app,
  and Screen Recording, Accessibility and Keychain access must be granted again.
- **System parsers.** RTF, ImageIO and PDFKit remain attack surface for clips that come from peers and sync.
